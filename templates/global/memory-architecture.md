# Архитектура памяти

Этот файл описывает общую файловую память между проектами и подключение к ней разных агентов. Прямое задание пользователя и действующие политики среды имеют приоритет. Память не предоставляет дополнительных разрешений на чтение, запись, делегирование или Git-операции.

## Старт и поиск общей памяти

1. Определи текущий домашний каталог пользователя средствами среды; не подставляй домашний каталог автора шаблона или другой машины.
2. Прочитай `.agents/memory-kit.conf` относительно этого home. Это UTF-8 файл данных с `VERSION=1`, `GLOBAL_MEMORY_DIR` и `KIT_ROOT`. Разделяй строки по первому `=`; оставшаяся часть — буквальное значение, включая пробелы, Unicode и знаки `=`. Пути абсолютные и не содержат CR, LF или TAB. Не исполняй файл через `source`, `eval`, dot-sourcing или другой интерпретатор команд.
3. Непосредственно прочитай `global-collaboration-rules.md` из `GLOBAL_MEMORY_DIR`, затем общую часть этой архитектуры и только протокол своего агента. Если актуальный текст уже есть в контексте, не загружай его повторно без причины. Обычная ссылка не импортирует содержимое автоматически.
4. Для проекта прочитай действующие инструкции `AGENTS.md`, затем `START-HERE.md`, относящиеся к задаче решения в `assistant-memory.md` и текущую очередь `memory/current-work-queue.md`.
5. Если локатор отсутствует, версия не поддерживается, пути недоступны или инструкции конфликтуют, сообщи конкретное ограничение. Не объявляй память загруженной по одному наличию файлов и не подменяй канонический источник найденной копией.

На Windows путь к локатору обычно выражается как `<текущий home>\.agents\memory-kit.conf`, в POSIX — `<текущий home>/.agents/memory-kit.conf`. Выбирай представление пути для активной оболочки; содержательные файлы памяти ради смены оболочки не переписывай.

## Слои и единый источник

| Слой | Файлы | Назначение |
|---|---|---|
| Машина | `.agents/memory-kit.conf` в текущем home | Единственное место настройки расположения общей памяти и исходного набора |
| Глобальный | `global-collaboration-rules.md`, `memory-architecture.md` в `GLOBAL_MEMORY_DIR` | Долговременные правила между проектами |
| Подключение агента | Короткий управляемый блок в штатном файле инструкций | Прочитать локатор, общую память и проектные инструкции |
| Старт проекта | `AGENTS.md`, `START-HERE.md` | Порядок чтения и карта проекта |
| Решения проекта | `assistant-memory.md` | Устойчивые соглашения и архитектура |
| Текущая работа | `memory/current-work-queue.md` | Актуальная очередь, статусы и следующие шаги |
| Хронология | `memory/YYYY-MM-DD.md` | Короткие проверенные результаты дня |
| Темы | `memory/topic-<slug>.md` | Развивающаяся тема и причины решений |

Не копируй общие правила в отдельные каталоги каждого агента. Общая память может находиться в произвольном каталоге, включая исторический `.codex/memories`: источник определяет локатор, а не имя каталога или время изменения файла. Не записывай в переносимые шаблоны абсолютные пути конкретной машины.

Ссылки между слоями предпочтительнее дублирования текста. Проектная архитектура и история реализации остаются в проекте. Внутренняя память харнесса помогает восстановить контекст, а проверенные устойчивые сведения сохраняются в канонических файлах по действующим правилам согласования. Факты, предположения и результаты проверок отмечай раздельно.

## Рабочий цикл

- Перед работой сверяй текущую задачу с очередью и реальным состоянием проекта. Память может устаревать.
- Ищи относящуюся к задаче тему доступным средством поиска, затем читай нужный фрагмент. Поиск в истории дополняет чтение канонических файлов.
- По завершении содержательного этапа фиксируй принятые решения, выполненные проверки и оставшиеся ограничения в подходящем слое. Объём записи соразмерен пользе; отдельный лог каждой операции не требуется.
- Соблюдай порядок изменения памяти из общих правил, включая явно согласованные исключения для служебных записей. Не вводи дополнительное согласование, если текущее задание уже разрешает действие.
- Не редактируй внутренние базы, индексы или сессионные файлы харнесса ради синхронизации с kit. Нативная история и файловая память имеют разные задачи.

## Создание каркаса и обновления

При явном запросе инициализировать проектную память прочитай `KIT_ROOT` из локатора и проверь наличие исходного набора. Из него запускай `scripts/memory-kit.ps1 init-project -Repo <целевой проект> -Agent <профиль>` на Windows либо `scripts/init-project.sh --repo <целевой проект> --agent <профиль>` в Bash. Команды используют общий каталог из локатора; явное изменение источника памяти должно быть осознанным.

`install` создаёт машинный локатор и глобальные точки входа. `KIT_ROOT` всегда соответствует выполняемому набору; `SourceRoot` выбирает только другое дерево шаблонов. `init-project` создаёт проектный слой и выбранные проектные адаптеры. Эти операции не являются массовым обновлением старых проектов. Если набор перемещён или недоступен, уточни актуальное расположение; не ищи исходники по жёстко заданному пути внутри Codex.

Существующие канонические файлы сохраняются по умолчанию. Для обновления управляемых блоков адаптеров используй `UpdateAdapters` / `--update-adapters`; окружающие инструкции и существующие содержательные файлы памяти сохраняются. `Force` / `--force` допускает также замену канонических файлов: перед таким действием изучи полный diff и сохрани пользовательские решения. Не используй принудительную установку как способ скрыть конфликт источников.

Экспорт v2 переносит исходный текст канонических файлов. Импорт формирует машинный локатор и блоки адаптеров для целевого home, не заменяя произвольные строки в пользовательской памяти. Абсолютные пути внутри старых заметок требуют отдельной сверки.

## Протоколы для конкретных агентов

Применяй общую архитектуру и только секцию, где назван твой харнесс. Название модели не определяет харнесс. Возможности, настройки и инструменты проверяй в фактической среде; они не являются обязательной зависимостью файловой памяти.

### Протокол для Codex

- Штатный глобальный файл — `AGENTS.md` в фактическом `CODEX_HOME`, обычно `~/.codex`. Непустой `AGENTS.override.md` может скрыть его; проверь действующую цепочку в новой сессии.
- Проектные инструкции зависят от рабочей директории и вложенных overrides. Домашний `~/AGENTS.md` не заменяет глобальный файл профиля.
- Пользуйся объявленными в текущей сессии skills и их действующими путями. Если источник недоступен, проверь доступные сведения установки и сообщи ограничение; наличие старой копии в cache не доказывает, что она активна.
- При ошибках Git или sandbox диагностируй фактического пользователя, разрешённые пути и состояние блокировки. Не удаляй чужой lock и не расширяй ACL или `safe.directory` по универсальному рецепту.

Источник: [официальная документация AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

### Протокол для DSH / DeepSeek Harness

- В стандартном профиле `dsh-agent-instructions` читает `$DSH_HOME/AGENTS.md`, затем `$DSH_AGENTS_HOME/AGENTS.md`, после чего проектные инструкции. Обычные корни — `~/.dsh` и `~/.agents`; состав профиля и плагин могут отличаться.
- Адаптер kit устанавливается в фактический `DSH_HOME/AGENTS.md`. Он направляет к общему машинному локатору, не создавая копию правил в DSH.
- Compaction, история и список задач доступны только в пределах возможностей установленного профиля. Устойчивые решения сохраняй в файловой памяти; внутреннее хранилище DSH для этого не изменяй.
- Как внешний исполнитель соблюдай границы задания, разрешённые пути и критерии готовности. Передавай проверенный результат и ограничения; правила общей памяти не расширяют полномочия исполнителя.

Источник: [DSH agent instructions](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/context/agent-instructions/README.md).

### Протокол для MiMoCode

- Глобальный адаптер — `AGENTS.md` в фактическом конфигурационном каталоге MiMoCode. Явный `MIMOCODE_CONFIG_DIR` имеет приоритет; стандартный каталог определяется настройками MiMoCode/XDG, обычно `~/.config/mimocode`. Не выводи его из расположения Desktop-приложения.
- MiMoCode может читать альтернативные инструкции совместимости и отключать проектную конфигурацию. Проверь активный профиль, если kit отсутствует в контексте.
- Если включены native memory/history tools, используй их как дополнительный поиск. Их индекс не означает автоматическую индексацию `GLOBAL_MEMORY_DIR` или `assistant-memory.md`.
- Нативные checkpoint, scratchpad и task progress полезны для продолжения сессии. Не создавай дубли канонических правил в `MEMORY.md` и не требуй конкретного внутреннего формата для работы с kit.

Источники: [MiMoCode instructions](https://github.com/XiaomiMiMo/MiMo-Code/blob/4e58a80184794d52d913d4b886b96f496f2c7020/packages/cli/src/session/instruction.ts), [конфигурационные пути](https://github.com/XiaomiMiMo/MiMo-Code/blob/4e58a80184794d52d913d4b886b96f496f2c7020/packages/shared/src/global.ts).

### Протокол для ZCode

- Штатный загрузчик читает `.zcode/AGENTS.md` внутри фактического home; рабочие инструкции проекта берутся из ближайшего `AGENTS.md`. Произвольный `ZcodeDir` в kit сам по себе загрузчик не перенастраивает. Пользовательские `priorityFiles` могут изменить или отключить загрузку.
- Если доступен `ReadSessionContext`, используй фокусный запрос к прошлой сессии, когда проектной памяти недостаточно; запрос для продолжения задачи применяй по его фактическому контракту. Не обещай полноту истории или безопасность запроса только из-за наличия compaction.
- Память проекта, включаемая самим ZCode, — отдельная необязательная возможность. Установка kit её не включает и не требует.
- Внутренние SQLite-схемы, индексы и checkpoints зависят от версии. Не используй их как публичный интерфейс kit и не восстанавливай репозиторий из них без явного разрешения.

Источники: [ZCode project instructions](https://zcode.network/en/docs/agents/#project-instructions-file), [загрузчик инструкций](https://github.com/zai-org/ZCode/blob/3c5b227649371507ddc4eb46ac5133afe6db1cab/apps/zcode-cli/packages/adapters/src/context/index.ts).

### Протокол для Antigravity

- Глобальный адаптер — `GEMINI.md` в каталоге Antigravity, обычно `~/.gemini`. Проектный адаптер kit — `.agents/rules/antigravity-memory-adapter.md` с YAML `trigger: always_on` и кратким `description`.
- Прочитай общий локатор и канонические файлы напрямую. Не встраивай большие файлы памяти через inline include: у rules есть собственные ограничения размера и контекста.
- Доступные планы, чеклисты, артефакты и транскрипты помогают продолжению беседы. Они могут сохраняться после её завершения, но не заменяют проектные решения и очередь. Физические пути и имена инструментов определяй по текущей среде.
- `/learn`, если доступен, предлагает rules/skills через отдельный review-процесс. Он не нужен для подключения kit и не заменяет общую память. Skills загружаются по необходимости; обязательный старт памяти остаётся в правилах.

Источники: [Antigravity Rules](https://www.antigravity.google/docs/rules/), [Hooks](https://www.antigravity.google/docs/hooks/), [Learn](https://www.antigravity.google/docs/commands/learn/).
