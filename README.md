# Codex Memory Kit

Переносимая файловая память для Codex, DSH (DeepSeek Harness) и других ИИ-агентов. Имя репозитория сохранено для совместимости; общая память не зависит от каталога конкретного харнесса.

## Архитектура

У системы один канонический источник каждого вида информации:

1. **Общая память между проектами:** `global-collaboration-rules.md` и `memory-architecture.md` в выбранном `GLOBAL_MEMORY_DIR`.
2. **Стартовые указатели:** короткие файлы в местах, откуда агент действительно загружает инструкции. Они направляют к общей памяти и проекту.
3. **Память проекта:** `AGENTS.md`, `START-HERE.md`, `assistant-memory.md`, очередь, ежедневные и тематические заметки в `memory/`.

История сессий, compaction, scratchpad и встроенные memory tools помогают восстановлению контекста. Устойчивые решения остаются в канонических файлах. Протоколы агентов описаны отдельными именованными секциями в `memory-architecture.md`; агент применяет общую часть и только свою секцию.

Обычная Markdown-ссылка не импортирует содержимое файла автоматически. Стартовый файл предписывает агенту прочитать общую память. Проверка файловой структуры не доказывает, что конкретная сессия её загрузила или соблюдает.

## Каталог Общей Памяти

Все команды используют один порядок выбора:

1. Явный `--global-memory-dir` / `-GlobalMemoryDir` имеет приоритет.
2. Явный `--codex-dir` / `-CodexDir` без общего каталога сохраняет историческое значение `<codex-dir>/memories`. Для нестандартного профиля Codex с общей памятью передавай оба аргумента.
3. Если существует только старый каталог `~/.codex/memories`, используй его без переноса.
4. Для новой установки, а также если существует только общий каталог, используй `~/.agents/memories`.
5. Если существуют оба каталога, команда завершается ошибкой и требует явно выбрать `GlobalMemoryDir`. Набор не определяет источник по дате файлов и не объединяет их автоматически.

Под «существует» понимается наличие каталога, включая пустой. `--home` / `-Home` задаёт домашний каталог для этого запуска. Пути `.codex` и `.dsh` по умолчанию вычисляются относительно него. Пользовательские `CODEX_HOME` и `DSH_HOME` нужно передать явно как `CodexDir` и `DshDir`; скрипты не меняют переменные среды или конфигурацию харнесса.

Разные агенты должны ссылаться на **один** выбранный каталог. Отдельные копии в `.codex/memories` и `.dsh/memories` создают конкурирующие источники правил. При этом существующая общая память может оставаться в `.codex`: название каталога не ограничивает круг её читателей.

## Стартовые Файлы

Параметр `--agent` / `-Agent` выбирает точки подключения:

| Значение | `install` | `init-project` |
|---|---|---|
| `codex` (по умолчанию, совместимость) | `<CodexDir>/AGENTS.md` | Общие проектные файлы |
| `dsh` | `<DshDir>/AGENTS.md` | Общие проектные файлы |
| `antigravity` | Без отдельного глобального адаптера | Общие файлы и `.gemini/rules/antigravity-memory-adapter.md` |
| `all` | Стартовые файлы Codex и DSH | Общие файлы и адаптер Antigravity |
| `none` | Без стартовых файлов харнесса | Только общие проектные файлы |

`~/AGENTS.md` создаётся дополнительно для совместимости; `--no-home-agents` / `-NoHomeAgents` отключает его создание и проверку. Этот файл не заменяет глобальную точку входа конкретного агента. Стартовые файлы Codex и DSH создаются из одного короткого шаблона и ссылаются на одни канонические файлы.

Codex загружает глобальные инструкции из `CODEX_HOME` (обычно `~/.codex`); непустой `AGENTS.override.md` имеет приоритет над `AGENTS.md`. В стандартном DSH с `dsh-agent-instructions` глобальная цепочка включает `$DSH_HOME/AGENTS.md`, затем `$DSH_AGENTS_HOME/AGENTS.md` (обычно `~/.agents/AGENTS.md`), далее проектные инструкции. Плагин может быть отключён или отличаться в установленной версии. Проверено по [документации Codex](https://developers.openai.com/codex/guides/agents-md) и [исходной документации DSH](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/context/agent-instructions/README.md) на 2026-10-20.

Установщик пишет в `.dsh/AGENTS.md`, чтобы не зависеть от поддержки общего корня в старых версиях DSH. Существующие инструкции в `.agents/AGENTS.md`, `.dsh/AGENTS.md` и `.codex/AGENTS.md` нужно сверить: набор не заменяет и не объединяет их автоматически.

## Установка

Репозиторий можно клонировать в любой каталог; его расположение не определяет место установки памяти. Уже имеющийся локальный checkout можно использовать повторно. Коннектор GitHub не нужен, если Git и доступ к remote уже работают.

```bash
git clone git@github.com:phoenix0597/codex-memory-kit.git ~/src/codex-memory-kit
cd ~/src/codex-memory-kit
```

Linux, macOS, WSL и Git Bash: Bash и стандартные `sed`, `grep`, `cp`. Нативная Windows: Windows PowerShell 5.1 или PowerShell 7+. Python требуется только для тестов.

### PowerShell

Из каталога набора установить DSH или сразу оба агента:

```powershell
.\scripts\memory-kit.ps1 install -Home $HOME -Agent dsh -NoHomeAgents -DryRun
.\scripts\memory-kit.ps1 install -Home $HOME -Agent dsh -NoHomeAgents
# Для обоих агентов: -Agent all
```

Для подключения к уже выбранной памяти задавай её явно:

```powershell
.\scripts\memory-kit.ps1 install -Home $HOME -Agent dsh -GlobalMemoryDir "$HOME\.codex\memories" -NoHomeAgents
```

Инициализация и проверка проекта:

```powershell
.\scripts\memory-kit.ps1 init-project -Repo C:\path\to\project -Home $HOME -Agent dsh
.\scripts\memory-kit.ps1 check -Repo C:\path\to\project -Home $HOME -Agent dsh -NoHomeAgents -Strict
```

Если общий каталог задан явно, передавай тот же `-GlobalMemoryDir` при инициализации, проверке, экспорте и импорте. Без `-Repo` команды `init-project` и `check` используют текущий каталог.

Для нестандартных профилей добавь `-DshDir <path>` / `-CodexDir <path>`. `-SourceRoot` выбирает дерево исходных шаблонов. `-VerboseLog` включает подробный вывод; `-Force` разрешает перезапись выбранных файлов только после разбора различий и согласования.

### Bash

```bash
./scripts/install.sh --home "$HOME" --agent dsh --no-home-agents --dry-run
./scripts/install.sh --home "$HOME" --agent dsh --no-home-agents
./scripts/init-project.sh --home "$HOME" --repo /path/to/project --agent dsh
./scripts/check.sh --home "$HOME" --repo /path/to/project --agent dsh --no-home-agents --strict
```

Поддерживаются `--global-memory-dir`, `--codex-dir`, `--dsh-dir`, `--source-root` (для установки и инициализации), `--project-name` (для инициализации), `--force`, `--verbose`. Пробный запуск `--dry-run` доступен для установки и инициализации. В Git Bash передавай абсолютные POSIX/MSYS-пути, например `/c/path/to/project`; в PowerShell — нативные Windows-пути.

### Подключение Внешнего Исполнителя DSH

1. Обнови исходный checkout через Git. Каталог набора внутри `.codex` — обычный исходный репозиторий; отдельное клонирование для DSH необязательно.
2. Выбери существующий канонический каталог общей памяти. Просмотри `install -Agent dsh -GlobalMemoryDir <path> -NoHomeAgents -DryRun` или соответствующую Bash-команду.
3. Если глобальные файлы или стартовый файл уже существуют, сравни их с новыми шаблонами. Обычная установка выводит `SKIP` и сохраняет содержимое. Нужные изменения существующей живой памяти согласуй и объедини отдельно; запуск установщика не обновляет пропущенные файлы.
4. Создай стартовый файл DSH и при необходимости проектный каркас. Для существующего проекта сохраняй его очередь, решения и заметки; не используй `Force` для «починки» стартовой цепочки без просмотра различий.
5. Запусти `check -Agent dsh -Strict` с теми же путями и с `-NoHomeAgents`, если домашний индекс пропущен.
6. Начни новую DSH-сессию из целевого проекта. Попроси перечислить реально загруженные инструкции, прочитанные общие файлы, текущую задачу и разрешённые пути. Сверь ответ с файлами. Только после этого считай загрузку проверенной.

Архитектура общей памяти не предоставляет исполнителю дополнительных прав. Область задачи, возможность делегирования, работа с global memory, Git push и запись вне проекта определяются фактическим заданием и средой.

## Обновление Существующей Установки

Переход на нейтральный каталог не обязателен. Самый безопасный первый шаг — сохранить существующий `GLOBAL_MEMORY_DIR` и подключить к нему DSH через стартовый файл. Это уже один общий источник без копирования правил.

Для переноса в `~/.agents/memories` сначала сохрани резервную копию, сравни и объедини реальные пользовательские правила, затем явно выбери новый путь во всех стартовых файлах и командах. Проверь проектные ссылки и загрузку обоих агентов. Набор не выполняет такой перенос молча и не удаляет старую память.

Обновление шаблонов в Git не меняет установленные файлы. Не применяй `Force` ко всем живым файлам: сначала diff, сохранение пользовательских правил и согласование конкретной замены. В репозитории хранятся переносимые шаблоны; персональная память пользователя в него не включается.

## Переменные Шаблонов

| Переменная | Роль |
|---|---|
| `HOME_DIR` | Домашний каталог целевого пользователя |
| `GLOBAL_MEMORY_DIR` | Единственный каталог общей памяти |
| `KIT_ROOT` | Абсолютный каталог исходного набора, вычисляемый из `SourceRoot` |
| `CODEX_DIR` | Каталог конфигурации именно Codex; сохранён для совместимости |
| `DSH_DIR` | Каталог конфигурации именно DSH |
| `REPO_ROOT` | Корень проекта |
| `PROJECT_NAME` | Имя проекта |

Синтаксис — `{{VARIABLE}}`. Все переменные путей поддерживают варианты `_POSIX` и `_WINDOWS`; `PROJECT_NAME` таких вариантов не имеет. `REPO_ROOT` и `PROJECT_NAME` доступны только при инициализации проекта. Неизвестный или незаполненный плейсхолдер приводит к ошибке рендера.

Общее имя `AGENT_HOME` не используется: на одной машине может быть несколько харнессов, а каталог общей памяти и расположение исходного набора выполняют другие роли. В общих шаблонах используй `GLOBAL_MEMORY_DIR`; реальные пути Codex оставляй под `CODEX_DIR` в его протоколе.

Пример значений: `examples/project-vars.env.example`. Это документация, а не файл конфигурации, который скрипты исполняют или читают автоматически. Исходники не содержат абсолютных путей пользователя; они подставляются при установке. Проектные ссылки остаются относительными к репозиторию, общие — указывают на выбранную память.

## Проверка

`check` поддерживает `--mode global|project|all` / `-Mode global|project|all` (по умолчанию `all`), выбор агента и `NoHomeAgents`.

В обычном режиме проверяется наличие обязательных файлов. В строгом режиме дополнительно проверяются незаполненные плейсхолдеры и стартовые ссылки на **выбранную** общую память. Совместимые ссылки относительно домашнего каталога также принимаются. Проверяется наличие выбранного адаптера Antigravity. Непустой `AGENTS.override.md`, скрывающий стартовый файл Codex, сообщается как ошибка для ручной сверки. Проверка никогда не меняет содержимое.

Коды возврата: `0` — успех; `1` — ошибка обычной проверки; `3` — ошибка строгой проверки; `2` — неверные аргументы или ошибка PowerShell-команды. Ошибка Bash-рендера возвращает ненулевой код. Статусы: `CREATE`, `SKIP`, `OVERWRITE`, `EXPORT`, `IMPORT`, `CHECK OK`, `CHECK FAIL`; пробный запуск добавляет `DRY-RUN`.

## Экспорт И Импорт

```powershell
.\scripts\memory-kit.ps1 export -Home $HOME -Agent dsh -Repo C:\path\to\project -OutputDir C:\path\to\export
.\scripts\memory-kit.ps1 import -Home $HOME -Agent dsh -Repo C:\path\to\project -InputDir C:\path\to\export
```

```bash
./scripts/export-memory.sh --home "$HOME" --agent dsh --repo /path/to/project --output-dir /path/to/export
./scripts/import-memory.sh --home "$HOME" --agent dsh --repo /path/to/project --input-dir /path/to/export
```

Новые экспорты используют `global/memories/`, необязательный `global/AGENTS.md`, стартовые файлы выбранных агентов в `global/agents/<agent>/AGENTS.md` и проектный слой в `project/`. Импорт также читает старый формат `global/.codex/memories/`. Оба глобальных файла обязательны. При `Force` копирование дерева обновляет совпадающие файлы, сохраняя отсутствующие в архиве пользовательские заметки.

Экспорт и импорт копируют реальные файлы без переписывания ссылок внутри пользовательского текста. При переносе на другую машину или в другой каталог нужно отдельно согласовать обновление путей и проверить стартовую цепочку. Импорт старого архива может потребовать создания новых стартовых файлов через `install`. Эти команды не являются автоматической миграцией и не заменяют резервное копирование или историю Git.

## Исходники И Тесты

- `templates/global/` — общие правила и архитектура с именованными протоколами агентов.
- `templates/agent/` — короткий стартовый указатель для харнесса.
- `templates/home/` — домашний индекс совместимости.
- `templates/project/` — каркас проекта и адаптер Antigravity.
- `scripts/lib-memory.sh` — общий контракт путей и рендера Bash-скриптов.
- `scripts/*.sh` и `scripts/memory-kit.ps1` — установка, инициализация, проверка, экспорт и импорт.

Интеграционные тесты работают в одноразовых домашних и проектных каталогах и проверяют новые и старые установки, нестандартные пути, кириллицу, повторный запуск, ошибки ссылок, экспорт и импорт:

```bash
python -m unittest discover -s tests -v
```

Тесты автоматически используют доступные Bash, Windows PowerShell и PowerShell 7. `MEMORY_KIT_TEST_BACKENDS=bash,powershell,pwsh` ограничивает список и требует наличия всех указанных сред. В Windows Bash означает Git Bash. Скрипты установки Python не требуют.

## Доступ Git На Windows

Если текущая среда Codex использует отдельного sandbox-пользователя и Git сообщает `dubious ownership` либо не может создать `.git/index.lock`, настройка доступа относится к этой среде, а не к общей памяти. Проверь реальное имя пользователя и минимально нужные права:

```powershell
git config --global --add safe.directory C:/path/to/repo
icacls "C:\path\to\repo\.git" /grant "MACHINE\SandboxUser:(OI)(CI)M" /T
```

В Git Bash при вызове Windows-команды отключай преобразование путей: `MSYS_NO_PATHCONV=1 icacls ...`. Это диагностический пример, а не действие установщика. Не переноси ACL или настройки разрешений Codex на DSH автоматически.
